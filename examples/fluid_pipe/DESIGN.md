# 流体管道系统设计文档（v2）

Minecraft 基岩版流体管道 Addon（sapdon 框架 TS 项目）。逻辑层与渲染层分离，事件驱动同步；流体基于**势**的物理概念模拟：从势高流向势低，向上爬升耗势，泵造势差，罐储液 32 格。

---

## 1. 概述

流体管道系统由**逻辑层 L**（图结构）与**渲染层 R**（分组结构）分离构成，通过事件驱动机制保持数据一致。

**代码结构（行为保持重构后）：**

```
scripts/
├── core/                 # 逻辑层 L：纯逻辑，无 @minecraft/server 依赖
│   ├── graph.ts          #   段图：节点/端点/段结构与洪水分段（EndKind/SegEnd/Segment/FloodGraph/floodSegment）
│   ├── potential.ts      #   势模型：常量 + 端点势 + 段内传播 + 全局势传播场（computePotential）
│   └── flow.ts           #   流动结算：前沿逼近势覆盖/罐吸排/泵抽水/流失（tickFlow）+ 渲染辅助（potCovered/bfsOrder/coveredOf/frontFromCovered）
├── engine/               # 渲染层 R：MC 引擎（@minecraft/server）
│   ├── const.ts          #   方块/物品/状态/持久化常量
│   ├── world.ts          #   方块读取：blockKey/keyParts/getBlockByKey/getAdjacent/isWaterlogged
│   ├── log.ts            #   运行时诊断日志（setRuntimeLog/rlog/logErr）
│   ├── state.ts          #   内存模型：设备表/段索引/缓存 + 设备注册与开关 + tickCount
│   ├── graph.ts          #   FloodGraph 接口的 MC 实现（读世界方块）
│   ├── rebuild.ts        #   结构重建：rebuildAround/rebuildPending/rebuildStale/写回连接状态
│   ├── render.ts         #   渲染：管道水态 + 罐液位写方块状态
│   ├── persist.ts        #   持久化：动态属性分块 save/load + 诊断
│   ├── tick.ts           #   主循环：每 20 tick 势求解 + 流动 + 渲染 + 设备存活检查
│   └── diag.ts           #   诊断：describeSegmentAt/dumpFluid
├── fluidCore.ts          # 门面：re-export core/*（保持旧导入路径可用）
├── fluid.ts              # 门面：re-export engine/*（保持旧导入路径可用）
└── index.ts              # 事件/命令/扳手入口
```

测试镜像 `test/fluid.test.mjs` 对应 `core/` 三个文件（纯逻辑无 MC 依赖，可直接在 Node 下镜像）。

## 2. 数据结构

### 2.1 逻辑层 L（段图结构）

| 字段 | 类型 | 说明 |
|------|------|------|
| 段 Segment | 对象 | 连续管道（`pass` 成员，阀门为端点设备不入段），洪水填充生成 |
| 端点 SegEnd | 枚举 | 设备（泵/罐/单阀/三通阀）· 管道端点 · 浸润 · 空气/墙 |
| 端点坐标 | key | `dim:x,y,z`（含高度，供势衰减计算） |
| 势场 pot | Map\<pipeKey, number\> | 段内每格势（传播场，随源变化重算） |
| hi/lo | SegEnd | 段内最高/最低势端点 |

**作用：** 存储所有节点，负责查询、关系维护、势传播与流动判定。

### 2.2 渲染层 R（分组结构）

| 字段 | 类型 | 说明 |
|------|------|------|
| 组名 | String | 段 id（组 = 段），用于标识和更新 |
| 维度 | String | 所在世界维度 |
| 成员 | List\<key\> | 该组包含的所有管道方块坐标 |

**作用：** 仅存管道方块位置，每 20 tick 按组批量更新流体动画（`fluid_pipe:core` 状态）。

### 2.3 数据关系

```
逻辑层 L（段图） ←── 事件驱动同步 ──→ 渲染层 R（分组）
      │                                    │
  势传播、流向判定                    批量更新显示
```

## 3. 核心机制

### 3.1 势的定义

势是流体在管道中的能量状态量，决定流动行为。

### 3.2 流动规则

流体从势高的端子流向势低的端子。

### 3.3 势的来源（源）与初始条件

| 条件 | 势值 | 说明 |
|------|------|------|
| 管道端子在水中（浸润） | 1 | 被浸润，获得初始势 |
| 开向空气的端子 | -1 | 作为势的汇（默认叠加），势 > -1 时流失 |
| 未满储液罐端口 | -1 | 作为汇吸入流体 |
| 满储液罐端口 | 0 | 停止吸入 |
| 储液罐（液位>0） | level/32 | 弱源，可排水 |

### 3.4 高度对势的影响

| 方向 | 势变化 |
|------|--------|
| 向上爬升一个管道 | 减势 1（消耗势能克服重力） |
| 向下流动 | 不减势（重力辅助） |
| 水平 | 不减势 |

系统计算的是流体到达目标所需的**最大势**：多源 BFS 传播，每个端点取到达它的最大剩余势。

### 3.5 泵造势

| 属性 | 值 |
|------|------|
| 默认方向 | **顶面 = 输出口（高压端），底面 = 输入口（低压端）**，侧面不参与 |
| 能量 | 常开 + 右键开关 |
| 造势 | **并联模型**：输出口 = 独立势源 **+Δ（4）**，输入口 = 势汇 **-Δ（-4）**；输入侧有水（源传播到达 或 输入段有罐液）才吐，防凭空造水 |

### 3.6 通断状态

- 单方向阀门：可旋转（放置时玩家可转，西/东为自身参考系）；开/关=`fluid_pipe:open` 状态（扳手只切换顶面箭头 →开/↑关，与三通统一箭头，方块朝向不动）；开=单向透传（valveIn→valveOut 耦合），关=全墙
- 三通阀：可旋转，**自身参考系** 西=输入、北/东/南=输出；`fluid_pipe:dir` ∈ {east,south,west,north}（顺时针循环），dir=west（指向输入）=全关；顶面单箭头指示当前方向
- 管道必须形成完整通路（所有途经端子均开）才流动

### 3.7 势的传播流程

```
源（水=1 / 泵输出=+Δ / 满罐=0）
    │
    ▼ 多源 BFS 沿段图传播（泵输出需输入侧有水，固定点迭代；三通透传）
    ├── 向上 → 势 -1/格
    ├── 向下/水平 → 势不变
    ▼
到达目标端点
    ├── 空气(-1)：势 > -1 → 流失
    ├── 罐：未满(-1)且势>-1 → 吸入 +1 格；满(0)且下游流失 → 重力排水 -1 格
    └── 泵输入(-4)：段内有水（源到达或罐有液）→ 泵吸水（抽罐 -1）
```

## 4. 方块设计

| 方块 | 规格 |
|------|------|
| 流体管道 | 连接单元；6 面 `pipe_connect` + `fluid_pipe:core`；可含水（浸润=源） |
| 泵 | 可旋转；**顶=输出/底=输入**；右键开关；贴图：顶/底 digitCircuit 风格 input/output 符号（白标于噪声底）、侧面 on/off 机身 |
| 单方向阀门 | 可旋转（放置时）；`fluid_pipe:open` 开/关（扳手只切顶面箭头 →/↑）；西=输入、东=输出（自身参考系）；关=全墙 |
| 三通阀 | 可旋转；`fluid_pipe:dir` ∈ {east,south,west,north}；西=输入、dir 面=输出；dir=west=全关；顶面单箭头指示 |
| 储液罐 | 不可旋转；**仅顶面可连管道**；液位 0~32 格；filled 0/1 渲染 |

## 5. 渲染与更新（势驱动）

- 更新频率：每 **20 tick**（1 秒）
- **有效管道**：段必须同时具有输入端点（泵输出 `END_PUMP_OUT` / 阀门输出 `END_VALVE_OUT`）与输出端点（罐 `END_TANK` / 阀门输入 `END_VALVE_IN` / 泵输入 `END_PUMP_IN`）才渲染水；孤立段、仅泡水段（`END_SOURCE` 不算输入）、仅空气端段无效
- **水流通路径（叶剥除）**：只渲染"连接所有输入/输出端点的最小管道子树"——死胡同支路（不指向任何输出端点）被逐层剥除，不会显示水；Y 形多输出各分支均渲染
- **势场决定路径/方向**：`computePotential` 每 tick 全量重算，势覆盖集合（`pot > -1` 的管道）= 水能到达的范围
- **渲染渐进逼近**：水前沿 `front` 每 tick 向势覆盖数逼近 ±FRONT_SPEED（填充慢涨、势消失/断段后渐渐退干），`tickFlow`（逻辑层）每 20 tick 计算并写入 `seg.covered`（含水管道集合）；引擎 `renderAll` 只读 `seg.covered`，方块存在即写 `fluid_pipe:core`（缓存去重），不存在记失效；罐液位写 `fluid_pipe:level`
- **泵泡水**：泵被水浸没（自身含水或相邻 6 面任一为水块）→ 直接吐水给输出段（`pump.soaked`，每 5 tick 刷新），无需输入侧管道
- 事件驱动重建：管道/设备放置破坏、设备状态变化（开关/旋转/三通方向/罐液位）、浸润变化 → 重建 L + R

## 6. 物品清单

| 物品名称 | 用途 |
|----------|------|
| 流体管道 | 基础传输单元，构成管道网络主体 |
| 泵 | 制造势差，驱动流体定向流动 |
| 储液罐 | 存储流体（32 格），作为源或汇 |
| 管道阀门（单方向阀门） | 单向通断：西入东出；扳手切换开/关（只转顶面箭头） |
| 三通阀 | 一入三出选择通断（西入，东/南/北输出；指向西=全关） |
| 管道扳手 | 点单阀旋转 90°、点三通顺时针切换输出、点泵开关、点管道/罐诊断 |

## 7. 系统交互总览

```
玩家操作（放置/破坏/旋转/开关/扳手）
    │ ▼ 触发重建
事件驱动机制（检测变化 → 标记受影响区域 → 重建）
    ├── 逻辑层 L：洪水分段 → 势传播场 → 流向
    └── 渲染层 R：按组更新流体动画
    │ ▼ 每 20 tick
玩家看到：管道中流体动画（按势方向流动）
```

## 8. 持久化

- 只存小状态：设备表（泵 on / 罐 level 0~32）+ 管道位置；阀开/关与三通 dir 均为方块状态（`minecraft:cardinal_direction` / `fluid_pipe:dir`），世界存档自动持久化，不入库
- 势场/段图不落盘：加载后 `rebuildPending` 按区块渐进洪水重建，`restoreFrontMode` 从方块状态恢复前沿
- 仅结构事件保存；运行态液位流动不落盘；写动态属性异常不可吞；loaded 门闩防覆盖
